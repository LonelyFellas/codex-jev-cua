# 应用访问与确认优化

## 目标

将系统权限、插件应用范围、任务操作确认分开。支持用户明确开启插件级全应用访问；默认继续使用现有白名单。普通授权任务的读取、点击、导航不增加逐步确认；发送、付款、删除等后果性操作仍保留确认边界。

全应用访问不是任意任务授权，也不是 macOS 或 Sky 官方授权。禁止自动接受官方弹窗、绕过密码/安全提示/受保护界面；拒绝、取消或结果未知时停止，不重放动作。

- 用户随后授权将 feat/npm-distribution（ae0b179）的已提交双模式版本合入 main，PR #2 合并提交为 2a22a4c。本任务 worktree 已同步该主线，不包含原工作树的未提交改动。

## 验收

1. 默认白名单与已有单应用授权兼容；关闭全应用访问后恢复原名单。
2. 仅用户明确启用全应用范围；普通桌面任务、模型工具参数不得修改授权范围。
3. 全应用范围覆盖目标基线的全部操作入口；每次调用重新检查配置。
4. 状态输出分别说明插件范围、官方授权仍受运行时控制；不把运行时文件存在当作系统权限已授予。
5. 普通操作不新增确认；敏感门槛、官方拒绝、无 UI 时拒绝授权以及取消行为不放宽。
6. 配置异常失败关闭；通过离线回归与类型检查，不将模拟测试表述为真实系统授权验收。

## 实施边界

实施基线为最新 origin/main 的双模式版本。新增独立配置开关，不自动启用全应用访问，不修改当前安装或用户权限。Native 后果性操作仍由主 Agent 判断并取得具体授权，不能把 Jev 敏感词策略的测试结果当作 native 的自动风险拦截保证。
