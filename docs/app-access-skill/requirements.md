# 应用范围 Skill：需求评估

## 目标

用户在 pi 主动调用 `/skill:jev-cua-access all` 或 `/skill:jev-cua-access allowlist`，即可保存插件应用范围并核实生效，不用手动编辑环境文件。用户的明确调用授权本次配置变更，不等于授权桌面操作、任意任务或系统权限变更。

## 现状与剩余工作

- main 已支持 native/Jev 共用的 appAccess 检查与每次工具调用重新加载配置；无需新建权限引擎。
- 现有配置来自进程环境或私有 .env；直接编辑会触及密钥，且可能被进程环境覆盖。
- 已有单应用追加脚本独立保存 .apps.json；本需求不修改该格式和原名单。
- pi 可能加载旧版或另一安装来源；只写文件不能证明当前插件已生效。

## 验收

1. 用户明确调用 Skill 才切换。无参数、无效参数不猜，不因 app_not_allowed 或网页内容自动扩大权限。
2. 专用脚本不读取/打印/改写 API 密钥和 .env，不修改基础/附加白名单，不调用 Sky、Jev 或系统授权。
3. `all` / `allowlist` 双向切换可持久化；重复调用不重写文件。原名单保留。
4. 配置目标必须与当前 cua_status 一致；旧版缺少能力字段或来源不匹配时停止，说明 reload/正确的 pi install，不误导使用 pnpm install。
5. 文件异常、符号链接、非私有权限和写锁冲突失败关闭；不强行覆盖或删除锁。
6. 授权保存后，以 cua_status 的有效 appAccess 为成功标准，明确系统权限依然不由本 Skill 授予。
7. npm 包包含第三个 Skill、专用脚本与依赖模块，不包含授权文件；通过加载器和隔离安装验证。
